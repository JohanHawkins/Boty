# 1. Nivel Básico (MVP / Prototipo Rápido)

## Estructura y Arquitectura

* Arquitectura **monolítica simple**
* Flujo:

  ```
  Usuario → Input → API LLM → Respuesta → Usuario
  ```

* Sin separación estricta de capas
* Uso de **webhooks o funciones serverless**
* Sin memoria persistente (o muy básica)

---

## Tecnologías y Herramientas

### Lenguajes

* JavaScript (Node.js) o Python

### Plataformas Low-Code / No-Code

* **n8n** (muy recomendado para ti)
* **Make (Integromat)**
* **Dialogflow (Google)**
* **Botpress**

### IA / APIs

* Veremos (buscar otras opciones más adelante)

### Almacenamiento

* JSON local
* SQLite (opcional)

---

## Metodologías de Desarrollo

### Metodología

* **Kanban (rápido y flexible)**

### Hitos (2–5 días)

1. Definir propósito de Boty (ej: soporte técnico, asistente personal)
2. Crear flujo básico (input → respuesta)
3. Integrar API LLM
4. Crear interfaz simple:

   * CLI / Web básica / WhatsApp (Twilio)
5. Pruebas manuales
6. Deploy simple (Render / Vercel)

# 2. Nivel Medio (Aplicación Funcional con Persistencia)

## Estructura y Arquitectura

* Arquitectura **Cliente-Servidor**
* Separación clara:

  ```
  Frontend → API Backend → LLM + DB
  ```

* Manejo de estado de conversación
* API REST o WebSockets
* Introducción de **memoria contextual**

## Metodologías de Desarrollo

### Buenas prácticas

### Hitos (2–4 semanas)

1. [x] Diseñar arquitectura cliente-servidor

# 5. Caso de Estudio: Analizador de Frases por Palabras Clave

> Modo demo: el backend identifica intenciones por palabras clave y ejecuta acciones según la frase del usuario.
>
> **Estado: implementado** en `backend/src/services/intent.ts` (normalización sin tildes, tokenización, banco de palabras → acciones, caso por defecto) y conectado al modo demo (`backend/src/services/llm.ts`). Tests en `tests/intent.test.ts`.

Escribe un código [especifica el lenguaje, ej. en Python / JavaScript / C#] que analice una frase de texto ingresada por el usuario y ejecute acciones automáticas según las palabras encontradas.

El programa debe cumplir con los siguientes requerimientos:

1. Entrada de texto: Recibir una frase o cadena de texto (string).
2. Procesamiento de texto:
   - Convertir la frase a minúsculas.
   - Limpiar signos de puntuación.
   - Dividir la frase en palabras individuales (tokens).
3. Banco de palabras y acciones (Diccionario / Mapa):
   - Definir un conjunto de palabras clave mapeadas a funciones o acciones específicas.
   - Ejemplo de palabras clave y sus acciones:
     * Si contiene "hola" o "buenos días": Ejecutar función `saludar()` -> Imprimir "¡Hola! ¿En qué puedo ayudarte?".
     * Si contiene "precio" o "costo": Ejecutar función `mostrar_precios()` -> Imprimir "Nuestros precios inician en...".
     * Si contiene "soporte" o "ayuda": Ejecutar función `contactar_soporte()` -> Imprimir "Transfiriendo con un agente...".
     * Si contiene "adios" o "salir": Ejecutar función `despedir()` -> Imprimir "¡Hasta luego!".
4. Comparación y ejecución:
   - Iterar sobre las palabras de la frase.
   - Compararlas contra el banco de palabras clave.
   - Si se detecta una coincidencia, llamar e invocar la acción/función correspondiente.
   - Manejar el caso por defecto: Si ninguna palabra coincide, mostrar un mensaje indicando que no se reconoció el comando.
5. Estructura del código:
   - Mantener el código modular, usando funciones claras para cada acción.
   - Incluir comentarios breves que expliquen el flujo de tokenización y comparación.
